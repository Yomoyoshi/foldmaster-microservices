1. «Бизнес-требования» (BRD)

	Цель документа: 
		Зафиксировать стратегические цели компании, которые должны быть достигнуты с помощью разрабатываемого сайта. 
		Этот документ — контракт между аналитиком и владельцем бизнеса.

	Название проекта: 
		Прототип интернет-магазина складной мебели
	Версия: 
		1.0
	Статус: 
		Согласован

1.1. Бизнес-контекст и проблема
	На данный момент компания продаёт складную мебель только через маркетплейсы.

	Проблемы: 
		высокая комиссия маркетплейсов, 
		отсутствие прямого контакта с клиентами, 
		невозможность собирать базу для повторных продаж (аксессуаров).

	Гипотеза: 
		создание собственного интернет-магазина позволит увеличить маржинальность и получить независимый канал сбыта.

1.2. Бизнес-цели (KPI)

	Номер: 			1 
	Цель: 			Проверить спрос на продукцию через собственный канал
	Метрика успеха: Получение минимум 10 реальных заказов в первый месяц после запуска
	Срок:			Первый месяц работы
		
	Номер: 			2
	Цель: 			Оценить удобство процесса заказа и оплаты для клиентов
	Метрика успеха: Доля успешно завершённых заказов (оплаченных и отправленных) от общего числа оформленных ≥ 60%
	Срок:			За 3 месяца

	Номер: 			3
	Цель: 			Создать основу для будущего масштабирования
	Метрика успеха: Сайт должен быть выполнен на технологиях, позволяющих добавить новые категории товаров без переписывания архитектуры
	Срок:			На этапе проектирования
		
	Номер: 			4
	Цель: 			Минимизировать операционные затраты на старте
	Метрика успеха: Администрирование сайта (обработка заказов) должно занимать у администратора не более 2 часов в день при 20 заказах в месяц
	Срок:			Сразу после запуска

1.3. Бизнес-ограничения (Out of the scope)

	- Нет интеграции с эквайрингом (оплата — только через СБП и банковские переводы по подтверждению менеджером).
	- Нет автоматической синхронизации с 1С или складскими системами.
	- Нет мобильного приложения — только адаптивный сайт.
	- Нет сложной CRM или системы лояльности на первом этапе.

1.4. Критерии успешности проекта (Acceptance Criteria)

	- Сайт запущен в открытом доступе по доменному имени.
	- Добавлены 3 модели кроватей-диванов с фотографиями и описаниями.
	- Форма заказа работает и отправляет данные администратору.
	- Администратор может менять цены и статусы заказов через интерфейс.
	- Первый заказ успешно обработан (полный цикл: заказ → звонок → оплата → отгрузка → отправка документов клиенту).

2. "Требованиями пользователя" (URD)

   Цель документа:
     Описать, кто будет пользоваться сайтом, какие задачи они решают, и какие сценарии взаимодействия с системой у них есть.

2.1. Роли пользователей

  Роль:      Покупатель
  Описание:  Физическое лицо, желающее приобрести кровать-диван. Может не иметь технических навыков.

  Роль:      Администратор	
  Описание:  Сотрудник компании (или владелец), который обрабатывает заказы, управляет каталогом, общается с клиентами.
  
2.2. Пользовательские истории (User Stories) (для Покупателя)

	ID:					        US-01
	Как(роль):			    Покупатель
	Я хочу (действие):  Увидеть список всех доступных моделей с ценами и фото
	Чтобы (цель):		    Быстро выбрать подходящий товар
	Приоритет:			    Высокий

	ID:					        US-02
	Как(роль):			    Покупатель
	Я хочу (действие):	Перейти на страницу конкретной модели по прямой ссылке из буклета или соцсетей
	Чтобы (цель):		    Увидеть детальную информацию и сразу оформить заказ
	Приоритет:			    Высокий

	ID:					        US-03
	Как(роль):			    Покупатель
	Я хочу (действие):	Заполнить форму заказа, указав имя, телефон и адрес
	Чтобы (цель):		    Отправить заявку на покупку
	Приоритет:			    Высокий
